# 上下文超限故障转移设计喵~

## 目标喵~

当上游返回 HTTP 400 且响应体明确包含 `context_length_exceeded` 时，代理不再直接把错误原样回传给客户端，而是切换到候选链中的下一个模型喵~

其他 HTTP 400 仍按现有行为原样回传，避免把客户端请求参数错误错误地隐藏为候选切换喵~

## 现有行为喵~

规则引擎按 `config.yaml` 中的规则顺序逐条匹配，首条命中即停止喵~

当前通用规则 `status: 400 -> passthrough` 会拦截所有 400，因此上游的上下文超限不会继续尝试后续候选喵~

## 设计喵~

在通用 `400 -> passthrough` 规则之前增加一条配置规则喵~

```yaml
- match:
    status: 400
    body_regex: 'context_length_exceeded'
  action: next
```

规则必须位于通用 400 规则之前，因为规则引擎采用首条命中优先级喵~

匹配范围只限错误标识符 `context_length_exceeded`，不匹配宽泛的 `context`、`token` 或自然语言错误描述喵~

## 数据流喵~

1. 上游返回 HTTP 400 和错误 JSON 喵~
2. `upstream.try_candidate` 将完整错误响应正文写入 `AttemptResult.error_text` 喵~
3. `proxy._run_one_candidate` 将状态码与错误正文交给 `rules.decide` 喵~
4. 上下文超限规则先于通用 400 命中，返回 `next` 喵~
5. 编排器停止当前候选并尝试候选链中的下一个可用模型喵~
6. 若没有后续候选，则维持现有“所有候选不可用”错误响应喵~

## 配置范围喵~

修改 `config.example`，使新部署默认具备该规则喵~

修改当前运行用的 `config.yaml`，使本地代理热重载后立刻采用该规则喵~

不增加代码内置特殊状态码，也不新增规则引擎字段喵~

## 错误处理喵~

错误正文缺失或不包含精确标识符时，上下文超限规则不命中，继续由通用 400 规则原样回传喵~

规则顺序被后续配置修改时，日志中的 `matched_by` 应显示实际命中的规则，便于排查优先级问题喵~

## 测试喵~

新增规则引擎测试，验证下列行为喵~

- `400 + context_length_exceeded` 命中 `next` 喵~
- 普通 400 错误仍命中 `passthrough` 喵~
- 通用 400 规则位于前面时会抢先匹配，以固定规则顺序是功能语义喵~

新增代理编排测试，构造首个候选返回上下文超限、第二个候选成功的场景，并验证代理选择第二个候选喵~
