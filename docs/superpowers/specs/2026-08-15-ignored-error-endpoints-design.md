# 接口错误忽略配置设计喵

## 目标喵

为不支持特定接口的中转站提供可选的接口级错误忽略配置，避免这类接口失败触发目标模式长时间重试或自动避险冻结，同时让控制台日志保持简洁喵。

典型场景是部分中转站不提供 `POST /v1/messages/count_tokens`，但普通消息接口仍然可用喵。

## 配置格式喵

在 `server` 配置段新增可选列表 `ignored_error_endpoints`，每项通过 HTTP 方法和路径精确匹配一个接口喵。

```yaml
server:
  ignored_error_endpoints:
    - method: POST
      path: /v1/messages/count_tokens
```

未配置该字段、配置为空列表，或请求未命中任何项目时，保持现有行为喵。

## 配置解析与规范化喵

`ignored_error_endpoints` 必须是列表；每一项必须是字典，并包含非空字符串 `method` 与 `path` 喵。

加载配置时将方法转为大写，并将路径规范化为单个前导 `/`，从而让 `post`、` POST ` 和 `v1/messages/count_tokens` 等等价写法获得一致匹配结果喵。

空方法、空路径、非字符串字段或列表元素类型错误时，配置加载失败并抛出 `ConfigError`，避免用户误以为配置已经生效喵。

解析后的配置保存为不可变 endpoint 标识集合，供请求路径快速判断喵。

## 请求处理语义喵

请求使用规范化后的 `method + path` 与配置集合进行精确匹配，不使用通配符，也不按查询字符串匹配喵。

命中忽略配置后，候选链内部仍遵守现有规则引擎的 `retry`、`next`、`freeze` 与 `passthrough` 语义；该配置只改变故障统计、外层目标模式和日志行为喵。

候选失败不会累计自动避险连续失败次数，因此不会因该接口不可用冻结候选喵。

所有候选失败后直接结束本次请求，不进入目标模式等待和下一轮重试喵。

接口最终仍返回现有的 `502`、`upstream_all_failed` 错误结构，客户端能够明确知道该接口没有可用上游喵。

## 日志语义喵

命中忽略配置后，不输出候选级失败 `warning`，避免每个候选和每次内部重试产生大量警告喵。

候选全部不可用时只输出一条 `info`，内容包含虚拟模型名和接口路径，例如喵：

```text
虚拟模型 auto-test 的接口 /v1/messages/count_tokens 全部不可用喵
```

已有成功日志、必要的调试信息和未命中接口的 warning 行为保持不变喵。

## 代码边界喵

配置模块负责解析和存储接口标识，不负责请求决策喵。

代理编排模块负责判断当前请求是否命中忽略配置，并将判断结果传入候选处理逻辑喵。

候选处理逻辑依据该标志跳过自动避险累计和候选级 warning 喵。

整条候选链处理逻辑依据该标志跳过目标模式外层循环，并输出唯一的最终 info 喵。

服务层、上游请求构造和响应协议不需要改变喵。

## 测试范围喵

补充配置解析测试，覆盖默认空列表、合法方法与路径规范化、错误类型和空值校验喵。

补充接口匹配测试，覆盖命中、方法不同、路径不同和查询字符串不参与匹配喵。

补充请求编排测试，验证命中接口时：候选仍按规则重试、自动避险不累计、目标模式不等待、最终响应仍为 `502` 喵。

补充日志测试，验证命中接口失败时只出现最终 `info`，不出现候选级 `warning`；未命中接口仍保持旧日志行为喵。

## 非目标喵

本次不新增路径通配符、正则匹配、状态码过滤或按候选配置忽略喵。

本次不改变客户端收到的错误状态码和错误响应 JSON 喵。

本次不改变普通消息接口和其他未配置接口的故障转移策略喵。
